# 27章：サービス：あらゆる存在 まとめ

## 要点

- サービス（マイクロサービス/SOA）は「分離」「独立開発・独立デプロイ」の神話で語られがちだが、それは幻想
- サービス分割は**縦軸の分離**には強いが、**横断的関心事**（横軸）には無力
- サービスを「コンポーネントの集合体」として設計し、SOLID（特に OCP/DIP）を守ることが本質
- 「サービスかモノリスか」ではなく「**境界線をどこに引くか**」が本丸

---

## 疑問①：「子猫の問題」って具体的にどういう話？

タクシー配車アプリで、サービスがこう分かれているとする：

- ドライバー検索サービス
- 配車サービス
- 支払いサービス
- 通知サービス

ここに新機能「子猫の配達サービス」を追加すると、全サービスに変更が波及する：

- ドライバー検索 → 子猫を運べるドライバーをフィルタ
- 配車 → 子猫運搬用の配車ロジック
- 支払い → 子猫運搬料金の計算
- 通知 → 「子猫が到着しました」メッセージ

Martin の主張：サービス分割は「縦軸の分離」（機能ごと）には強いが、「横軸の関心事」（新ユースケース）が現れると、結局全サービスを触る羽目になる。これが**横断的関心事の問題**。

## 疑問②：「救世主のオブジェクト」って何？ どのサービスの話？

Martin の答えは「**各サービスの中で OO の抽象を使え**」。子猫機能の影響を受けるサービス全部で、共通の抽象（`Rideable`）に依存させる。

```ruby
# 抽象（共通インターフェース）
class Rideable
  def pickup_location; end
  def delivery_location; end
  def calculate_fare(distance); end
end

# 具象
class PersonRide < Rideable
  def calculate_fare(distance)
    BASE_FARE + distance * RATE_PER_KM
  end
end

class KittenRide < Rideable
  def calculate_fare(distance)
    BASE_FARE + distance * RATE_PER_KM + KITTEN_HANDLING_FEE
  end
end

# 各サービスは Rideable に依存するだけ
class DispatchService
  def dispatch(rideable)
    # rideable が人か子猫かを知らなくていい
  end
end

class PaymentService
  def charge(rideable)
    fare = rideable.calculate_fare(distance)
  end
end
```

各サービスは抽象（`Rideable`）に依存するだけ。新しい運搬物が増えても、各サービスの中の既存コードは変更不要。

ただしモヤモヤが残る：「結局各サービスに新クラス追加するなら、全サービス触ってないか？」 → これは次の節で解決する。

## 疑問③：それでも全サービスを触ることになるのでは？

→ 「コンポーネントベースのサービス」が答え。各サービスを「**抽象 + プラグイン群**」として設計する。

```
配車サービス
├─ Rideable 抽象（共通インターフェース）
├─ Dispatch のコアロジック
└─ プラグイン
    ├─ PersonRide コンポーネント
    └─ KittenRide コンポーネント ← 新規追加
```

子猫機能追加時の動き：

1. 新しい `KittenRide` コンポーネント（1個のパッケージ）を作る
2. それを配車サービス・支払いサービス・通知サービスに**プラグインとしてデプロイ**する
3. 各サービスのコアコードは**一切変更しない**

Rails でのアナロジー：Gem として切り出して、各サービスの `Gemfile` に追加するだけ、というイメージ。

```ruby
# 各サービスの Gemfile
gem 'person_ride'
gem 'kitten_ride'  # 子猫機能はこれを追加するだけ
```

## 疑問④：横断的関心事と縦軸の分離って？

サービス分割は縦軸（機能の分離）には有効。でも認証・ロギング・新機能対応みたいな「横軸の関心事」は、各サービスに散らばる。

```
                縦軸（サービス境界）
                ↓
┌──────────┬──────────┬──────────┐
│ ドライバー │  配車     │  支払い   │ ← 縦の分割
├──────────┼──────────┼──────────┤
│ 認証      │ 認証      │ 認証      │ ← 横軸
├──────────┼──────────┼──────────┤
│ ロギング   │ ロギング   │ ロギング   │ ← 横軸
├──────────┼──────────┼──────────┤
│ 子猫対応   │ 子猫対応   │ 子猫対応   │ ← 横軸
└──────────┴──────────┴──────────┘
```

解決策は同じ：横軸の関心事を**共通コンポーネント**として切り出し、各サービスにプラグインとしてデプロイする。

実際に Rails でここまで徹底するのは少ないが、Martin の理想と現場の落とし所のグラデーションとして理解しておく。
